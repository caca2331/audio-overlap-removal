# 真实场景目标与验收准则

本文记录 `audio-overlap-removal` 在真实直播素材上的背景、生产目标、可接受损失和
后续优化方向。它用于避免后续实验重新把“听感完全消除”误当成唯一目标。

## 1. 背景与测试素材

- 早期人造测试均能通过，但算法进入真实直播场景后会留下明显 artifact。
- 真实测试使用：
  - `extra-asset/miyako.webm`：主播与媒体混合后的直播音频。
  - `extra-asset/sr.webm`：嵌入 `miyako` 的已知媒体参考。
- 两个主要连续匹配段约为：
  - `miyako 375–3695s`，offset `81.533s`。
  - `miyako 3695–4613s`，offset `81.463s`。
- 真实残留不像单纯编码误差。复杂传递函数、居中媒体先验和参考引导的
  频谱清理均能继续降低残留，但媒体中的人声一直比其他声音更难消除。
- 当前稳定检查点为 commit `06e548c`。后续 1.25×、1.5×、2.0× 实验继续
  扩大居中媒体人声清理；从 1.25× 开始已经能听到主播音质受影响，最佳
  听感边界在其附近。
- 统一参数 `--strength` 使用开放刻度：`0` 为保真优先，`1` 对应 v8
  激进档，`1.25/1.5/2` 对应现有 v9 档。2.0 不是代码硬上限；更高值属于
  未充分验证的 ASR 导向实验区，不应仅凭媒体残留能量决定生产默认值。
- 音频消除本身峰值资源低于 1GB；生产后级的人声分离与 ASR 当前允许 RAM
  和显存峰值各不超过 8GB。

## 2. 生产目标的真实优先级

完整分离且无损保留主播当然最好，但生产链还会经过人声分离和 ASR，因此
允许一定的可察觉音质损失。最终验收以 ASR 的说话人归属和内容保留为主。

按优先级排列：

1. **主播与媒体人声重叠时，ASR 必须稳定转录主播，而不是媒体人声。**
2. **主播没有说话时，ASR 最好不要转录残留媒体人声。** 少量媒体误转录
   可以接受，不要求音频能量严格归零。
3. **主播低语、轻声和短语气词不能因“低能量 = 静默”的判断被系统性删除。**
4. 主播音色尽量自然，但只要后续人声分离不会丢掉主播、ASR 内容保持稳定，
   轻微失真可以接受。
5. 主播侧可能还有不属于移除范围的 BGM 或其他媒体。轻微可察觉影响可以
   接受，该项低于主播人声和 ASR 正确性。

换言之，生产目标不是：

> 在所有时间点把参考媒体残留的波形能量压到最低。

而是：

> 尽量保留主播可识别语音；重叠时让 ASR 选择主播；无主播时尽量减少媒体
> 人声造成的错误字幕。

## 3. 当前实验事实

### 人声分离

- 媒体人声只有在前级已经把它削弱到较低程度时，BS-Roformer 才会进一步
  将其丢弃。
- 当前测试中主播人声没有被人声分离器整体丢弃。

### ASR

固定使用以下生产链：

```text
消除输出
  -> BS-Roformer vocal separation
  -> VAD-ASR（large-v3-turbo, language=ja）
  -> ASR stabilize profile 0
  -> *-raw.srt
```

v8 保守、v8 激进、v9 1.25×、v9 1.5×、v9 2.0× 五档的结果：

- 稳定化后字幕数为 26–29 条。
- 归一化文本两两字符相似度约为 95.4%–98.2%。
- 所有核心主播句子在五档中均存在；差异主要是断句、同音字和很短的语气词。
- 没有观察到清理强度增加后系统性漏掉主播内容。
- v9 1.5× 在 90 秒边界外出现过一条额外 `え?`，属于 ASR 边界/幻觉问题，
  不是主播被删除的证据。

### 低语风险

把真实主播语句衰减后叠入已知无主播区间，当前 v8 静默清理的保留增益约为：

| 叠加音量 | v8 保留增益 | 静默清理 2× |
| --- | ---: | ---: |
| -12dB | 0.75 | 0.67 |
| -24dB | 0.33 | 0.23 |
| -36dB | 0.20 | 0.15 |

因此不能继续用更高的纯能量阈值换取静默段更干净；这会首先伤害低语。

## 4. 后续验收指标

每次候选版本都应走完整的人声分离与 ASR，不再只比较波形能量。

| 场景 | 主要指标 | 验收方向 |
| --- | --- | --- |
| 主播与媒体人声重叠 | 主播文本召回、媒体文本侵入 | 主播句必须保留，媒体句不应取代主播句 |
| 只有主播 | 主播文本召回、短语气词召回 | 不得因清理强度增加而系统性下降 |
| 主播低语 | 低语文本召回或人工可辨识度 | 作为硬保护项 |
| 只有媒体人声 | 媒体错误字幕条数/字符数 | 越少越好，允许少量残留 |
| 主播侧额外 BGM | 主播文本召回 | 音质可轻微变化，不能影响主播 ASR |

听感和能量指标仍保留，但降为诊断指标：

- 主播主观音质与可察觉失真。
- 静默段残留 RMS。
- 与参考媒体相关的残留能量。
- 人声分离前后媒体 vocal stem 能量。

## 5. 建议的调整方向

### 5.1 停止无上限增强全局音频清理

全局居中清理在 1.25× 附近已进入主播音质受损区间，而 ASR 中尚未出现系统性
主播漏词，且 v8 已满足当前样本中“重叠时 ASR 转录主播”的硬目标。因此默认
从 v8 激进档开始；只有新增重叠样本出现媒体文本取代主播文本时，才在约
1.0–1.25× 之间做更细扫描，例如 1.10、1.15、1.20、1.25。没有证据支持把
1.5× 或 2.0× 作为默认生产参数。

### 5.2 在字幕层利用已知参考媒体去污染

这是最贴合生产目标的下一步：

1. 对参考媒体的 vocal stem 运行一次 ASR，并按媒体时间轴缓存。
2. 使用已知 `miyako ↔ sr` 对齐关系，把参考媒体字幕映射到直播时间轴。
3. 对输出 `raw.srt` 的每个片段，同时比较时间重叠和文本相似度。
4. 当输出字幕与同时间参考媒体字幕高度相似时，将其标记为媒体候选。
5. 只对高置信媒体候选做删除或降权；模糊情况保留。

该策略直接对应验收目标：

- 重叠时，现有 ASR 倾向输出主播文本，与参考媒体文本不同，因此保留。
- 主播静默时，残留媒体人声若被 ASR 转录，通常会与参考字幕匹配，因此可以
  在字幕层删除。
- 主播低语与参考媒体文本无关，不会仅因能量低而被删除。

已知例外是主播恰好复述媒体台词。第一版应使用保守的时间与文本双阈值；
后续可增加说话人 embedding 或人工复核标记，而不是直接扩大音频抑制。

### 5.3 静默增强只能使用主播保护信号

如果仍需输出更干净的音频，可将静默增强做成可选第二模式，但不能仅依赖
残差能量。至少需要以下一种保护：

- 从参考媒体无人声区间自动采集主播声纹，做主播相似度保护。
- 使用对低语敏感的语音检测，再结合参考媒体 vocal 活动判断来源。
- 只在“参考媒体 vocal 活跃且没有主播身份信号”时做强清理。

在可靠保护建立前，静默增强不应超过当前 v8 强度。

## 6. 当前推荐决策

- `06e548c` 继续作为稳定音频检查点。
- 当前生产基线优先使用 v8 激进档；媒体-only 字幕污染优先在字幕层处理。
- 仅当新重叠样本证明 v8 会让 ASR 选择媒体时，才向 v9 1.25× 方向细调。
- 以“主播重叠召回不下降”为硬门槛，以“媒体-only 错误字幕减少”为主要收益。
- 下一项高价值工作是参考媒体 ASR 对齐后的字幕去污染，而不是继续追求所有
  artifact 的听感归零。
